# aMember Pro Laravel 2.0.0

A Laravel integration update with expanded REST access, fluent parameters, response-format fixes, and a complete documentation set.

## Added

- Direct resource accessors: `userGroups`, `userNotes`, `userConsent`, `billingPlans`, `productCategories`, `productCategoryRelations`, and `invoiceItems`.
- `getInvoiceRefunds($id)`, `savedForms($id)`, and `deleteAccess($id)`.
- `where()`, `paginate()`, and `parameters()` request helpers.
- Laravel integration tests with Orchestra Testbench, standalone regression tests, and a PHP/Laravel CI matrix.
- English and Russian guides, full endpoint and parameter references, recipes, troubleshooting, issue templates, and Composer discovery metadata.

## Fixed

- Reusing the client no longer concatenates previous endpoint paths.
- Request parameters preserve zero, false, and empty strings.
- Shared request dispatch preserves form encoding for POST and PUT.
- Provider aliases resolve the same service and configuration loads without publishing.
- XML and serialized wire responses are preserved as strings instead of being decoded as JSON.
- Duplicate user-group method declaration removed before release.

## Compatibility and migration from 1.x

- Laravel dependencies are explicitly constrained to 10, 11, and 12. Use a PHP version supported by your Laravel version; the CI matrix uses PHP 8.1 for Laravel 10, PHP 8.2 for Laravel 11, and PHP 8.3 for Laravel 12 and 13.
- Invalid query options now throw `InvalidArgumentException`: count must be 1–1000, page must be nonnegative, order must be asc/desc, and format must be json/xml/serialize.
- Check Access service methods now use GET with only their documented arguments and always decode JSON. Review proxies or logging policies that distinguish GET query strings from POST bodies.
- XML and serialized responses appear as raw strings in the configured wrapper's `data` field. Serialized responses are not unserialized.
- The response wrapper remains Collection by default. The JSON adapter preserves upstream HTTP status in the body; its outer response status remains 200 unless set by the application.
- Older facade services retain mutable options. Use new concrete services or fresh dedicated resource builders for independent queries.
- The stale, empty library lock file is removed. Source checkouts resolve development dependencies with Composer; consuming applications retain their own lock files.

Laravel 10 and 11 compatibility jobs permit advisory-affected development dependencies only inside isolated CI runners, because Composer currently blocks these older framework versions. Laravel 12 and 13 keep advisory blocking enabled. This exception is not included in the package's Composer configuration.

## Install or upgrade

```shell
composer require plutuss/amember-pro-laravel:^2.0
```

Review your application's dependency constraints before upgrading. See [the documentation](https://github.com/plutuss/amember-pro-laravel/blob/2.0.0/README.md) for examples and response handling.
